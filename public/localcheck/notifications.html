Notifications

A source-linked table of each notification type, its trigger, destination, wording location, and record.

Inbox and phone push are separate. The inbox reads persisted rows from public.notifications. A push worker separately attempts device delivery based on the user’s push preference and registered tokens. Me → Activity is a different event feed. This page maps checked-in source; it is not a live database query or a new device test.

Shared system locations

  • services/notificationService.ts — notification types, fetch order/limit, read state and push preferences/tokens.
  • context/NotificationContext.tsx — notification state, refresh/realtime and opening notifications.
  • app/notifications.tsx — Settings notification inbox UI.
  • send-notification Edge Function — push eligibility, delivery attempts and retries.
  • Database records: public.notifications, public.push_tokens, public.push_delivery_attempts, and public.activity_events.
